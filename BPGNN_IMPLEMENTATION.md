# BPGNN implementation map

This artifact implements the paper pipeline as a 2+1 execution:

`Dealer preprocessing -> S0/S1 online computation`

The executable party identifiers inherited from the framework are `1=DEALER`,
`2=SERVER (S0)`, and `3=CLIENT (S1)`. Here `CLIENT` is the name used by the
original runtime for the second computing party; it is not the graph owner in
the BPGNN paper.

## Reused components

- FSS DPF and GTDCF: `ext/FSS/dpf.cpp`
- GTDCF ReLU API: `GTDCFReLU` in `ext/FSS/api.cpp`
- Beaver-style matrix and element-wise multiplication: `MatMul2D` and
  `ElemWiseMul`
- Secure output layer: `BPGCNSoftmax`
- Standalone four-protocol Softmax comparison: `softmax_comparison`
- Communication, key serialization, masks, and statistics: existing FSS runtime

All keys, multiplication correlations, and masks are generated by `DEALER`.

## New or replaced components

- `ext/FSS/include/FSS/graphiti.h` defines the executable graph routing plan.
- `ext/FSS/graphiti.cpp` implements real Propagate, identity ApplyE, and
  additive Gather over graph edges. This replaces the old `MockShuffle` path.
- `BPMPLGraphitiRouting` in `ext/FSS/api.cpp` implements:
  1. base Graphiti execution;
  2. DPF-based masked ghost-state extraction;
  3. Graphiti execution on the ghost-augmented delta graph;
  4. folding ghost destinations back into base destinations;
  5. secure degree normalization.
- `tests/e2e/BPGNN.cpp` runs MatMul -> BPMPL -> GTDCF-ReLU -> MatMul -> BPMPL ->
  Softmax and reports time, online communication, and Dealer preprocessing
  communication for every layer.
- `tests/bench/graphiti_test.cpp` checks Graphiti aggregation semantics.

## Softmax comparison benchmark

`softmax_comparison` compares four 2-compute-party + 1-Dealer paths on the
classification-output dimensions of Cora (2708x7), Citeseer (3327x6), or
Pubmed (19717x3):

- **BPGNN**: the framework's `BPGCNSoftmax` scaling-and-squaring protocol.
- **SIGMA**: the existing framework `Softmax` implementation (secure maximum,
  SiRNN negative-exponential LUT, reciprocal LUT, and secure normalization),
  exposed through `SIGMASoftmax` for this benchmark.
- **BumbleBee**: a framework-native implementation of BumbleBee's clipped
  negative-domain limit approximation, using `Texp=-14` and `n=6`.
- **CryptGNN/CrypTen**: a CrypTen-style limit-exponential baseline with eight
  squaring rounds. It uses this framework's secure maximum and reciprocal
  primitives; it is not a copy of the Python CrypTen runtime.

After building, execute the Dealer first and then parties 2 and 3 in separate
terminals:

```bash
./softmax_comparison 1 127.0.0.1 cora
./softmax_comparison 2 127.0.0.1 cora
./softmax_comparison 3 127.0.0.1 cora
```

Replace `cora` with `citeseer` or `pubmed`. Party 3 prints protocol time,
online/offline communication, MAE, maximum absolute error, and mean row-sum
error. The Dealer-to-client output-mask transfer used only to verify accuracy
is deliberately excluded from reported protocol communication.

All three newly implemented normalization paths keep exponentials, row sums,
reciprocals, and outputs at the configured fixed-point scale. In particular,
`InverseLUT` is called with `(scale, scale+10)`; using `(scale+4, 32)` would
either introduce a factor-of-16 error or shift small Cora denominators to LUT
index zero.

The BPGNN Softmax clamp uses `GTDCFClamp`, which evaluates the `x+L` and `x-L`
GTDCF branches together and reconstructs both masked branch outputs in one
batched round (per 65,536-element chunk). Its fast scaling-and-squaring path
uses `k=3`: one polynomial square followed by three restoration squares, for
four exponent multiplications instead of the original six. Scale-down,
polynomial rescaling, restoration rescaling, and final normalization use the
framework's one-round `EdabitsPrTrunc` probabilistic truncation; the reciprocal
index reduction remains exact.

All Softmax/ReLU comparison rows and every end-to-end BPGNN stage now report
three time columns: wall-clock `Total`, measured FSS `KeyRead`, and
`Online=Total-KeyRead`. The per-protocol CSV output likewise separates key
reading, pure online evaluation/reconstruction, and their sum. Runtime counters
are reset by every `FSS::start()` so six-query dataset experiments do not carry
timing values from one round into the next.

## ReLU comparison benchmark

`relu_comparison` evaluates the complete first-hidden-layer activation tensor
for each dataset: Cora `2708x64`, Citeseer `3327x64`, and Pubmed `19717x64`.
Inputs are signed 64-bit ring elements with 12 fractional bits and plaintext
values sampled from `[-8,8]`. It reports total protocol time, online traffic,
Dealer preprocessing traffic, and the number of incorrect outputs.

The five benchmark paths are:

- **OblivGNN**: the framework's existing `Relu2Round`, matching the paper's
  DPF comparison, output-bit flip, and secure multiplication structure.
- **CryptGNN/CrypTen**: the same secure comparison/selection core plus seven
  explicit synchronization barriers, producing a nine-round online schedule.
  This models CrypTen's round latency inside the C++ runtime but is not a port
  of CrypTen's Python bit-protocol communication payload.
- **GROTTO**: the framework's dedicated `GrottoReLU` backend. It evaluates the
  exact two-piece spline (`0` for a negative input and `x` otherwise) using
  rotated DPF prefix-parity queries and a ternary masked multiplication. See
  `docs/GROTTO_RELU.md` for the full protocol mapping.
- **SIGMA**: `SlothRelu`, consisting of `SlothDrelu` followed by secure
  `Select`. Although `SlothDrelu` internally invokes the DPFET comparison
  primitive, the complete `SlothRelu` composition is benchmarked as SIGMA,
  not as the GROTTO spline protocol.
- **BPGNN-GTDCF**: `GTDCFReLU` with the configured eight-bit suffix table.

Run the Dealer to completion first, followed by parties 2 and 3 in separate
terminals:

```bash
./relu_comparison 1 127.0.0.1 cora
./relu_comparison 2 127.0.0.1 cora
./relu_comparison 3 127.0.0.1 cora
```

Replace `cora` with `citeseer` or `pubmed`. The output-mask transfer used only
for correctness checking is excluded from communication measurements.
All five paths process at most 10,000 activations per key batch so that the
Pubmed experiment does not materialize more than one million FSS key packs in
memory at once.

## Graphiti scope

The previous framework code cannot be retained as a Graphiti implementation:
it swaps only the first and last entries and estimates shuffle overhead using
constants. The replacement executes the correct sparse graph functionality.

This is intentionally the simplified 2+1 variant requested for the artifact.
The Dealer prepares masks and FSS material, while the routing plan is supplied
to both computing processes. Consequently, this implementation measures the
cryptographic payload computation but does not claim to implement Graphiti's
full topology-hiding oblivious-shuffle preprocessing. Replacing the public
`GraphitiGraph` plan with Graphiti's three-order secret-shared DAG-list and
2+1 oblivious permutation is the remaining step if topology-hiding itself must
also be benchmarked.

## Three-dataset benchmark

The benchmark is split into `BPGNN_Cora`, `BPGNN_Citeseer`, and `BPGNN_Pubmed`.
Each executable uses the standard node, edge, feature, and class dimensions of
one dataset. The archive does not contain the raw edge files, so it constructs
a deterministic sparse graph with the same `(N,E)` size. Each executable runs
six queries:

1. round 1 performs static full-base inference and prepares the base Graphiti
   plan;
2. rounds 2-6 append 10 incremental vertices and 5 ghost aliases, reuse the
   cached base Graphiti plan and cached first-layer base transformation, and
   prepare only the small delta plan.

The executable prints every round's layer breakdown, the static result, the
average of the five dynamic results, and the static-to-dynamic ratio for time,
online communication, and Dealer preprocessing communication.

The computing parties stream preprocessing keys from `server.dat` and
`client.dat` (`memBuf=false`) instead of loading the complete files into RAM.
GTDCF-ReLU also processes at most 10,000 keys per chunk.

Static queries have no delta vertices or ghost aliases. The implementation
therefore skips ghost reconstruction and delta Graphiti when their sizes are
zero. The common reconstruction routine also returns immediately for an empty
array. BPMPL emits progress messages before and after ghost reconstruction and
secure normalization to distinguish computation from a peer synchronization
wait.

Run one dataset at a time. For example, Cora:

```bash
./BPGNN_Cora 1
./BPGNN_Cora 2 127.0.0.1
./BPGNN_Cora 3 127.0.0.1
```

Replace the executable name with `BPGNN_Citeseer` or `BPGNN_Pubmed` for the
other datasets. Let party 1 finish generating `server.dat` and `client.dat`
before starting parties 2 and 3. Running party 1 for the next dataset replaces
the previous dataset's preprocessing files.
